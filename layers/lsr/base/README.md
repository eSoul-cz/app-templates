# Layer `lsr/base`

Minimal LSR + RoadRunner + Inertia 3 (Vue 3) application, built on the `lsr-inertia` variant (`common` + `lsr/base`). The builder does not copy this file into the target project.

It is based on the layout of `esoul-internal` with the improvements of `code-hunt-game`: a Loader without JSON in exceptions, `UPLOAD_DIR` from the environment, `web` / `csrf` middleware groups, `tests/bootstrap.php` with `noDb`, and the newer `lsr/*` versions. Project specifics (mockups, leads, game, commerce, Elasticsearch, Redis, author headers) are stripped.

What the target project gets: `GET /up` (route `health`, `App\Http\Controllers\Health`) and `GET /` rendered by `App\Http\Controllers\Home` through Inertia into `assets/js/pages/Home.vue`, the Latte layout `templates/@layout.latte`, Vite 8 + Tailwind 4 + shadcn-vue (Button only), RoadRunner (`http` and `fcgi`, `jobs`, `scheduler`; no SSR), the Docker image (`development` / `production` targets), dev and CI compose files, an operations `README.md` and an `app:install` command that applies `config/migrations/migrations.neon`.

## Draft assumptions

- `lsr/*` versions are the current Packagist releases, equal to the `code-hunt-game` lock (`core` 0.7.0, `orm` 0.4.1, `routing` 0.5.1, `roadrunner` 0.1.19, `inertia` 0.1.9, `db` 0.3.17). `esoul-internal` (core 0.5.0) was not retested against them.
- Locks are not shipped (the builder renames the Composer package, which invalidates a `composer.lock` content hash; `pnpm-lock.yaml` would pin stale versions). The Dockerfile and `pnpm install --frozen-lockfile` need both locks, so run `composer install && pnpm install` and commit the locks right after creating a project.
- Debug mode comes from `[General] DEBUG` in `private/config.ini` (as in the reference projects) or, new, from the `APP_DEBUG` environment variable. `PRODUCTION` is its negation. Docker dev sets `APP_DEBUG=true`.
- The default `lsr.session` setup `init()` recurses into `App::getRequest()` while `App` is being built, so `config/di/extensions/lsr.neon` removes it (`setup!: []`). The file session then starts lazily, and the RoadRunner `HttpWorker` initializes it per request. Both reference projects replaced the session with a Redis one; no Redis is included here.
- Cache: Nette file storage with SQLite journal in `temp/` (no Redis). `ext-redis` stays required because `lsr/caching` requires it.
- No `lsr/auth`, `lsr/cqrs`, `lsr/otel`, SSR, text catalog or gettext/translation loading. `LsrExtension` still wires `Translations` (`cs_CZ` default), so the layout reads `translations->getLangId()`; `languages/` does not exist.
- `app:install` and `page_info` (key-value `App\Core\Info`) are kept because `docker/prepare-runtime.sh` runs the installer and `DbInstall` stores table versions there. `Seeder` and user types were removed. `migrations.neon` has no project tables.
- `scheduler` runs as a RoadRunner service although no jobs are registered; the RoadRunner `jobs` pool and the `tasks` boltdb pipeline exist but no task handlers are registered.
- RoadRunner serves the compiled assets itself through the `static` middleware (`/var/www/public/build/assets` symlink created by the Dockerfile / `prepare-runtime.sh`), as in `esoul-internal`; nginx is only used for development (`docker/nginx/nginx.conf`: FastCGI to RoadRunner `:9000` and a proxy to Vite `:5173`). `access_logs: true`, `max_request_size: 10` MiB are my defaults.
- `BrowserCsrfMiddleware` reads the public origin from the request itself: the scheme of the request URI and the `Host` header. Behind NGINX over FastCGI these come from the `HTTPS` and `HTTP_HOST` FastCGI parameters (verified against RoadRunner); `X-Forwarded-*` is ignored, because it is only safe when the proxy replaces it (the production snippets do, a plain `include fastcgi_params` does not). It is simplified from `code-hunt-game` (no `ForwardedRequestUri`, no translated message).
- FastCGI: `.rr.yaml` has `http.fcgi.address: tcp://0.0.0.0:9000` next to the HTTP listener on 8001 (health check, smoke test). The dev NGINX uses `fastcgi_pass app:9000` with the same parameters as the production host (`HTTP_HOST`, `HTTPS`, `X-Forwarded-*` replaced), so development exercises the production path.
- Jobs queue: the `tasks` pipeline uses the `boltdb` driver with the file `/app/temp/queue/tasks.db`, inside the persistent `./temp` mount of the `lsr-roadrunner` stack shape (no infrastructure change). `cache:clean` only removes `_*` entries of the cache storage and `prepare-runtime.sh` only removes `temp/*.php*`, so the directory survives them; the application README warns against deleting `temp/queue/` with the caches. A second LSR project that needs more state revisits a dedicated `./data` mount.
- Clock: the application clock is UTC (`APP_TIMEZONE` in `include/constants.php`, `date_default_timezone_set()` in `include/load.php`) and the database session is pinned with the PDO init command `SET time_zone = '+00:00'` (`config/di/environment.php`; it runs on every reconnect). The business time zone belongs in `CONTEXT.md`. Existing LSR apps that run on `Europe/Prague` keep it until they migrate (CHANGELOG note). `lsr/db` and `lsr/orm` have no time-zone handling of their own (nothing in their sources refers to a zone), so they follow the PHP default zone and the session zone, which are now both UTC.
- Network guard of the tests (`tests/Support`): the outgoing HTTP client is the DI service `http.client` (`App\Http\Client\CurlHttpClient`, PSR-18, declared with `Psr\Http\Client\ClientInterface` as its type) and a test replaces it with `Tests\Support\Http\FakeHttpClient::install()`; the PHPUnit extension `NetworkGuardExtension` registers a stream wrapper for `http` and `https` that opens localhost through the original wrapper and throws `NetworkAccessBlocked` for every other host. Raw sockets and cURL are not intercepted (review covers them). `phpunit.xml` excludes the groups `sandbox` and `quarantine`; `composer test` runs with `XDEBUG_MODE=off` and `composer test:coverage` with coverage.
- Git LFS: `common` sends `assets/**` to LFS, `append/.gitattributes` takes `assets/js/**` and `assets/css/**` out of it again (`!filter !diff !merge text`), because the Vite sources live there; client material elsewhere in `assets/` stays in LFS.
- MariaDB `12.3` in both compose files, the series the shared production server runs (`ansible/roles/mariadb`, `mariadb_series`). Dev DB password is a throwaway default (`dev-db-password`, overridable by `DB_PASSWORD`), CI uses fixed CI-only values.
- PHPStan level 10 without a baseline. The 10 errors the shipped code had at level 10 are fixed in the code (the `mixed` values read from the database, the cache and the environment are checked before use, `getTableNameFromClass()` uses `is_subclass_of()`). PHP-CS-Fixer rules come from `esoul-cz/coding-standard` (`Config::create()` in `.php-cs-fixer.php`; originally `code-hunt-game`'s rules; `composer cs` / `composer cs:fix`; there is no `cbf` alias).
- Mutation testing: `infection/infection` (`^0.35`, as in `code-hunt-game`) with a generic `infection.json5` (source `src`, tmp and logs in `temp/tools/infection`, no ignores, no MSI threshold). `composer mutation` (changed lines against the local `main` branch) and `composer mutation:full` are local and optional, never a CI gate; both need a coverage driver (Xdebug or PCOV). The `code-hunt-game` split into a Paratest coverage run and an Infection run is not copied: Infection runs the suite itself.
- Health: `GET /up` is registered in `routes/10-public.php` outside every middleware group (no Inertia, no CSRF). It returns `200 {"status":"ok"}` while `SELECT 1` on `db.connection` succeeds and `503 {"status":"unavailable"}` otherwise, with `Cache-Control: no-store`. The check is the `App\Http\Health\DatabaseCheck` interface (autowired to `ConnectionDatabaseCheck` in `config/di/services-common.neon`), so tests use a double. The worker still starts the file session and sends `Set-Cookie` for this route (`lsr/roadrunner` `HttpWorker` does it for every request); no session file is written per call (checked: the `temp/` file count does not grow).
- Docker `HEALTHCHECK` (production stage) is `curl --fail http://127.0.0.1:8001/up` (`curl` is in the base image), interval 10 s, start period 30 s. `docker-compose.ci.yml` only tightens the timing and `up --wait` waits for it; `docker/http-smoke.php` checks `/up` first.
- Every route has `->name()` (`health`, `home`).
- `Jenkinsfile` is composed from the library steps that exist today (`fullPhpTest`, `fullNodeTest`, `dockerComposeSmokeTest`, `dockerBuildMultiArch`, `deployKomodoStack`): checks (PHPStan, `composer cs`, tests, `composer audit`, ESLint, Prettier, `tsc`, Vitest, `pnpm audit`, build), a local build of the production image with the Compose smoke test, then the multi-architecture release from `main` / `master` and the optional deployment (`stack`). A comment names the planned one-call `lsrPipeline` (plan J4) that replaces it; the file was only syntax-checked (Groovy compile), not run on Jenkins.
- Frontend: TypeScript strict mode, ESLint 10 flat config (`@typescript-eslint/no-explicit-any` enabled via the recommended TypeScript set; no `shadcn-vue` lint rules; `no-restricted-imports` keeps application code on `@/design-system` and the design system free of Inertia, pages and components), Prettier plugins `organize-imports` and `tailwindcss`, Vitest with one unit test and the `shared` / `isolated` project split of the Laravel template (`isolate: false` for speed, files with `vi.mock()` isolated). The tree follows the `package/inertia-vue` guideline: shadcn-vue primitives in `assets/js/design-system/ui`, a curated `assets/js/design-system/index.ts` (`AppButton`) and `cn()` in `assets/js/utils/classes.ts`; `components.json` aliases point there. The scripts are `eslint`, `eslint:fix`, `format:check`, `format`, `tsc`, `build`, `test`. `app.scss` and `sass-embedded` are dropped; `assets/css/tailwind.css` is the only stylesheet. Icons (`lucide`) are not a dependency yet; add `@lucide/vue` when shadcn components need it. `pnpm-workspace.yaml` has `minimumReleaseAge`, `allowBuilds` and `auditConfig.ignoreGhsas` (dated entries for the dev-only advisories in Vite's optional `stylus` peer and in the shadcn-vue CLI, review 2026-12-23).
- `docker/http-smoke.php` checks the Inertia HTML and JSON responses, the compiled asset URLs, that private paths return 404 and, over FastCGI (`HTTP_SMOKE_FASTCGI_ADDRESS`, default `tcp://127.0.0.1:9000`; a minimal FastCGI client in the script, no extra package), `/up` and the Inertia JSON of `/` with `HTTPS` and `HTTP_HOST` set.
- The `development` target copies Node into the PHP image (as `esoul-internal` does); `startDev.sh` runs `pnpm install --no-frozen-lockfile`.
- `App::run()` is overridden (as in `esoul-internal`): `lsr/core` otherwise `readfile()`s any existing non-PHP file below the application root (e.g. `config/di/services.neon`) and calls `exit()`, which also kills the worker. RoadRunner's `static` middleware serves the public assets instead; everything else answers 404. Request paths ending in `.php` are routed like the path without it (core behaviour), they never serve file contents.
- The `lsr/*` packages stay under the owner's vendor (`Heroyt/lsr-*`); they are not mirrored or forked into the eSoul organisation (owner decision, V2).

## Verified

V2 pass (2026-11-23): `bin/templates build lsr-inertia`, then in the build `composer install --ignore-platform-req=php`, `composer phpstan` (level 10, no baseline, no errors), `composer cs`, `composer test` (40 tests, including the network guard, the HTTP client against the PHP built-in server and the container binding of `http.client`), `pnpm install`, `pnpm run eslint` (also confirmed to reject an import of `@/design-system/ui` outside the design system), `tsc`, `format:check`, `test`, `build` and `pnpm audit` (clean with the dated ignores in `pnpm-workspace.yaml`). `git check-attr` reports no `filter` for `assets/js/app.ts` and `assets/css/tailwind.css` and `filter: lfs` for `assets/images/*.png`. Docker: `docker build -f docker/Dockerfile --target production`; `docker compose -f docker-compose.ci.yml up --wait` and `http-smoke` (HTTP and FastCGI requests) passed against RoadRunner 2025.1.15 + MariaDB 12.3; `temp/queue/tasks.db` was created and survived `cache:clean`; the database session reported `time_zone = +00:00` while the global setting was `SYSTEM`; the dev `docker/nginx/nginx.conf` was run in `nginx:alpine-slim` in front of the image (FastCGI): `/up`, the Inertia page and a `POST` through `BrowserCsrfMiddleware` (same origin 200, other origin and forged `X-Forwarded-Host` 419; the route was a temporary test route). Mutation testing was not rerun; the `development` target (Vite + HMR) was not started.
